# FreshFlow NumPy Data Analyst Assignment

A beginner-friendly, end-to-end NumPy project for the fictional FreshFlow Juice Company. It loads a numeric CSV, audits data quality, calculates business metrics, compares products/outlets, studies daily trends, registers anomalies and compares discount scenarios.

## Requirements

- Python 3.10+
- NumPy (`pip install -r requirements.txt`)
- No Pandas or database is used.

## Project structure

```text
freshflow-project/
├── data/
│   └── freshflow_sales.csv       # generated by the script
├── outputs/                      # reports created by the analysis
├── tests/
│   └── test_freshflow.py         # eight independent tests
├── generate_data.py              # reproducible 5,000-row CSV generator
├── freshflow.py                  # NumPy analysis pipeline
├── requirements.txt
├── README.md
└── .gitignore
```

## Run it

Open a terminal in this folder:

```bash
python -m pip install -r requirements.txt
python generate_data.py
python freshflow.py
python -m unittest discover -s tests -v
```

Optional paths:

```bash
python generate_data.py --output data/freshflow_sales.csv --seed 42
python freshflow.py --input data/freshflow_sales.csv --output outputs
```

The generator uses a fixed seed (42 by default), so the same dataset can be recreated. It creates exactly 5,000 numeric transaction rows over days 1–30, with three outlets and eight products. Deliberate quality cases are inserted to support the assignment's validation work. The CSV is generated locally because the assignment DOCX says it is not supplied.

## Input columns

| Column | Meaning |
|---|---|
| transaction_id | Unique transaction identifier (deliberate duplicates included) |
| day_index | Observation day, 1–30 |
| outlet_id | Outlet code, 1–3 |
| product_code | Product code, 1–8 |
| category_code | Product category code |
| quantity | Units sold |
| unit_price | Selling price per unit |
| unit_cost | Cost per unit |
| discount_rate | Discount fraction, 0–1 |
| stock_before_units | Stock before the sale |
| payment_code | Payment method code, 1–4 |
| customer_rating | Rating from 1–5; missing values are allowed |

All CSV fields are numeric. Missing numeric values are stored as blank CSV cells and loaded as `NaN`.

## Outputs

- `final_report.json`: dataset profile, data dictionary, column ranges, quality counts, metrics, comparisons, descriptive statistics, daily trends, scenarios, findings and limitations.
- `cleaned_sales.csv`: valid financial-analysis rows plus calculated metric columns.\n- `quality_report.csv`: flagged transaction IDs and reason codes. Raw input is never overwritten.
- `daily_trend.csv`: 30-day net revenue, gross profit, units sold, day-to-day absolute/percentage revenue changes, a trailing 7-day average and unusual-day flags.
- `anomaly_register.csv`: IQR/z-score revenue outliers for review.

## Data handling decisions

- Missing customer ratings are flagged but do not remove otherwise valid financial transactions.
- Missing price/cost, invalid quantity/discount, duplicate IDs, invalid business codes and product/category mismatches are excluded from financial calculations.
- Unusually high prices/discounts and zero stock are flagged for investigation; they are not silently changed.
- Gross margin is calculated from total gross profit divided by total net revenue, not by averaging row-level margins.
- Scenario analysis holds quantity, price and cost constant. It is a what-if comparison, not a demand forecast.
- Gross profit is not net profit because operating expenses are outside the dataset.
- A 30-day sample cannot establish annual seasonality.

## Syllabus topics used

The code uses variables, numeric data types, input/output, operators, Boolean conditions, nested conditions, `for`/`while`-style iteration through loops, lists, indexing and slicing, dictionaries, functions, parameters, return values, modules/imports, NumPy arrays, array indexing, aggregation, vectorized operations, broadcasting-compatible arithmetic, statistics, filtering, sorting/group comparisons and debugging/tests. The project intentionally stays with the NumPy-only CSV workflow required by the assignment.
